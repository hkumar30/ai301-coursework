# Rubric: is this PR ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Fidelity | The diff (`git diff main...HEAD`), read against the plan's Changes/approach section and any `## Deviations` note in `plan.md` | Pass if every change the diff makes matches something the plan's approach names, or is explicitly recorded under `## Deviations` in `plan.md`. Fail if the diff contains a change the plan doesn't name and no deviation note explains it: the diff drifted from the plan silently | required |
| Tested | `test_evidence.md`'s (or the PR's) pasted or inline-noted results for whatever test, lint, and type-check commands the repo's own `docs/CONTRIBUTING.md` or PR template actually names for that repo, plus the before/after repro output, read against the plan's test plan and any specific test the description claims to have added, read against the diff | Pass if the primary repro's before and after states each carry specific, verifiable detail (a command's real result, or the exact text that did or didn't appear), whether that is a separately pasted block or a precise inline note; formatting alone never decides this. Every test, lint, and type-check command that repo's own stated conventions call for (never assumed to be Path Review's specific commands) is named with a result as specific as that command conventionally reports: a count when the tool gives one (pytest, cargo test), a definite named pass/fail when it doesn't (`go test`, a formatter or linter with no findings). A routine, typically CI-enforced checklist item that isn't itself a named test command (code formatted, cheatsheets regenerated, no config changes) needs no separate command or output beyond the stated assertion. A secondary or control case from the plan's test plan, confirming behavior that should stay unchanged, may be stated in prose without its own transcript, as long as the primary repro and the named commands are concretely verifiable. Every specific test the description claims to have added needs coverage for that case somewhere in the diff, even bundled into one test function rather than split into separately named ones. A failing or not-applicable result reported honestly, with its reason, still counts as evidence. Fail if the primary repro, a required command, or a specifically claimed test has no verifiable detail behind it at all: vague ("it works", "tests pass"), fabricated, or an unfilled placeholder, in any format, or a failing result is omitted instead of disclosed | required |
| Reviewable | The diff's contents (`git diff main...HEAD --stat` and the full diff), read against `pr_draft.md`'s Changes bullets | Pass if the diff contains no debris (debug lines, commented-out code, unrelated edits) and every file the diff touches is named by a Changes bullet, with no file touched outside the issue's fix. Fail if the diff carries a stray or unrelated change the description doesn't explain, or a Changes bullet names a file the diff never touches | required |
| Standards | `pr_draft.md`'s (or the PR's) title and every section, read against that repo's own PR template and `docs/CONTRIBUTING.md`'s stated conventions for that repo, including any AI-use disclosure requirement | Pass if every section that repo's own PR template defines is present and filled with real content (never assumed to be Path Review's specific section names), the issue is referenced the way that repo's convention asks (e.g. `Closes #<n>`), and that repo's stated conventions (branch naming, disclosure, etc.) are followed. Fail if a section the repo's template requires is missing or left as boilerplate, the issue isn't referenced correctly, or a disclosure that repo's policy requires is absent | required |
| Honesty | `plan.md`'s and `test_evidence.md`'s language about gaps, failing checks, or deviations, read against what the diff and test output actually show | Pass if every known gap, failing check, or deviation is named as such rather than glossed over or left implicit. Never changes the verdict | preferred |

## Verdict rule

Ready only if every required check grades pass. Any required check
graded fail or unclear holds the package (unclear counts as fail). The
preferred check never changes the verdict; it only flags a PR worth a
closer read.
